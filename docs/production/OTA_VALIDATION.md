## Safety and failure evidence

Tests cover disabled/missing/invalid OTA opt-in, wrong project/channel/package, unsafe API or public values, Firebase service accounts, native release version reuse, missing signing inputs, UI/native/unknown-path classification, unregistered runtime, public-environment drift, wrong update group, cross-channel routing, invalid rollout, missing Expo/GitHub credentials, missing required reviewers and untrusted source runs/artifacts.

The staged publisher exports once and calls EAS with the validated export directory. Production and rollback tests assert republishing the source group without exporting again. A rollback must explicitly select previous accepted evidence and use 100 percent. Ambiguous network failures never cause automatic retries or rollback; pre-publication and bootstrap audit receipts preserve the result for investigation.

Only protected publishing steps receive `EXPO_TOKEN`. PR validation has no Expo token, signing inputs or Play credentials. Production uses a required-reviewer environment, validates its policy through GitHub, checks the exact successful master source run and unexpired artifact, and rechecks native/environment/remote-group identity before republishing. Personal Expo tokens inherit account permissions; channel isolation is enforced by the reviewed tooling and routing, not by claiming channel-scoped tokens.

No custom runtime reload code was introduced. Built-in startup checks, zero launch wait, embedded fallback and anti-bricking behavior remain enabled. Automated config tests establish these settings; they do not replace device testing of offline/interrupted downloads or store/auth/payment flows.
